# @backlogg/api-client

Typed client for the backlogg backend API. It ships:

- `openapi.json` — the OpenAPI document exported from the FastAPI backend
  (`app.openapi()`). This is the **committed input** to the type generator.
- `src/schema.d.ts` — TypeScript types generated by
  [`openapi-typescript`](https://openapi-ts.dev) from `openapi.json`
  (also committed).
- `src/index.ts` — `createApiClient(baseUrl, options?)`, a factory returning a
  fully typed [`openapi-fetch`](https://openapi-ts.dev/openapi-fetch/) client,
  plus re-exports of the useful schema types (`paths`, `components`,
  `operations`, `webhooks`).

## Usage

```ts
import { createApiClient } from "@backlogg/api-client";

const api = createApiClient(process.env.API_INTERNAL_URL!);

const { data, error } = await api.GET("/v1/movies", {
  params: { query: { genre: "science-fiction", limit: 20 } },
});
```

The base URL is **always passed in** — it is never hardcoded in the client.
Schema paths already include the `/v1` prefix.

## Regenerating types when the backend changes

Whenever the backend API changes, regenerate the schema and types from the repo
in one step:

```bash
pnpm --filter @backlogg/api-client gen:api
```

This runs `scripts/gen-api.mjs`, which:

1. Exports the OpenAPI document from the Python backend
   (`uv run python -c "import json,backlogg.main as m; print(json.dumps(m.app.openapi()))"`,
   run from the repo root — no database required) into `openapi.json`.
2. Runs `openapi-typescript ./openapi.json -o ./src/schema.d.ts`.

After running, **re-commit both** `openapi.json` and `src/schema.d.ts` so the
generated types stay in sync with the schema in version control.

> Requires the backend toolchain (`uv`) available on `PATH`. In CI, generate the
> schema in a job that has the Python environment set up before typechecking the
> frontend.

To only regenerate the types from an already-updated `openapi.json`:

```bash
pnpm --filter @backlogg/api-client gen:types
```
